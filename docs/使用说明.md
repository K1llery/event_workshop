# 事件工坊 1.0.0

适用：Windows《以撒的结合：忏悔+》单人模式。使用原版 Lua API，不需要 REPENTOGON。已按本机 Mod Config Menu Chinese 1.12 的接口开发；其他 MCM 版本使用相同公共接口，但尚未实机确认。没有 MCM 时可以通过游戏控制台完整编辑规则。

## 开始使用

1. 将 event_workshop 文件夹放入游戏安装目录的 mods 文件夹。
2. 重启游戏，在 Mods 列表启用 Event Workshop - 事件工坊。
3. 进入一局单人游戏，按 F10 或你的 MCM 快捷键打开菜单，找到“事件工坊 Event Workshop”。
4. 在“规则”选择规则并开启“启用此规则”，配置“条件”和“动作”。
5. 在“运行”打开“本局运行规则”总开关。

安装时附带“清房生成随机底座”和“清房不充能”两条规则，均默认禁用。总开关与规则开关都开启才会运行。

配置在每次编辑后自动保存。规则执行次数、本局开关和随机状态也会保存。新局、R 重开会关闭总开关；继续已有的一局会恢复总开关、次数及开局事件标记。配置跨局保留，规则各自的启用状态也保留。

“开局补触发”的意思：本局首次打开总开关时执行一次当前方案中启用的开局规则。例如在第三个房间首次启用“开局给予 5 金币”，就在当前房间增加 5 金币。模组不会重开游戏、切换种子、重置角色或传送房间。同一局重复开启、继续游戏、切换方案或导入配置，都不会再次补触发开局事件。首次启用时没有开局规则，也视为这个机会已经使用。

## MCM 页面

| 页面 | 功能 |
| --- | --- |
| 运行 | 本局总开关、状态、种子、方案创建/复制/切换/删除、自检 |
| 规则 | 选择、新增、复制、删除、启用规则，选择事件 |
| 条件 | 概率、每 N 次、房间、角色、持有道具、执行上限 |
| 动作 | 多个动作及其顺序、类型和参数 |
| 道具 | 名称/ID 搜索，浏览结果，用于动作或持有条件 |
| 预设 | 添加常用规则、导出配置 |

数字和选项用左右键调整，按钮用确认键执行。删除按钮有确认弹窗。最多 20 套方案、每套 100 条规则、每条 20 个动作。新建规则和复制出的规则默认禁用；切换、创建或复制方案会关闭总开关。

道具页面提供字符选择与追加搜索，支持键盘和 MCM 的手柄导航。长名称或中文搜索可以在控制台输入 ew search 名称，然后回到 MCM 浏览全部结果。道具显示名称和 ID，包括其他模组注册的非隐藏道具。若安装 EID，可使用它提供的名称翻译；没有 EID 时使用游戏 API 提供的名称，不增加运行依赖。

MCM 的公共接口没有通用文本输入框，规则和方案重命名、配置 JSON 导入通过控制台操作。动作页面固定显示各类参数，只有与所选动作相关的参数参与执行。

## 事件和条件

| 事件 | 控制台值 | 说明 |
| --- | --- | --- |
| 清理房间 | room_clear | 原版清房奖励回调后延迟一帧执行；允许重复战斗清房 |
| 进入房间 | new_room | 每次进入时触发，含重新进入已清理房间 |
| 进入新楼层 | new_level | 原版进层回调 |
| 开局 | run_start | 本局首次启用总开关时补触发一次 |
| 玩家受伤回调 | player_damage | 接收原版伤害回调后延迟一帧；忽略 DAMAGE_FAKE |
| 击杀敌人 | enemy_kill | 敌对活跃 NPC 死亡后延迟一帧；包括环境造成的死亡，排除友军 |
| 使用主动道具 | use_active | 接收使用回调后延迟一帧，不改变道具本身效果 |

全部条件同时满足。先检查房间、角色、持有道具，再计入“每 N 次”，最后检查概率和执行上限。上限以规则执行次数计算，一个规则中的多个动作只算一次。动作失败仍占用一次，以避免重复尝试造成循环。

| 条件字段 | 范围/含义 |
| --- | --- |
| chance | 0–100，概率百分比；0 永不触发 |
| every | 1–999，每 N 次符合静态条件的事件执行 |
| roomType | -1 不限；其他为菜单支持的 RoomType 值 |
| character | -1 不限；其他为角色 ID，支持自定义角色 |
| collectible | 0 不限；其他为必须持有的道具 ID |
| maxRoom | 0 不限；1–999，同一房间的执行次数上限 |
| maxFloor | 0 不限；1–999，同一楼层的执行次数上限 |
| maxRun | 0 不限；1–999，本局的执行次数上限 |

房间和楼层上限不会因为离开再进入而清零；规则开关和总开关也不清零。删除旧规则后新建/复制的规则使用新 ID，按新规则计数。导入配置会清空本局规则计数并关闭总开关，保留开局事件已触发标记。

## 动作参数

| 动作 kind | 功能/字段 |
| --- | --- |
| spawn_collectible | 生成底座；itemId、amount；随机时使用 pool、qualityMin、qualityMax |
| give_collectible | 直接给予道具；参数同上；给予主动道具遵循原版槽位行为 |
| spawn_pickup | 生成掉落物；pickupVariant、subtype、amount |
| coins / keys / bombs | 增减资源；amount 可为负，扣除不会使数量为负 |
| hearts | 增减生命；heartType、amount，实际受角色生命机制限制 |
| charge | 调整主动充能；slot、amount，不能突破道具及电池的充能上限 |
| spawn_enemy | 生成菜单中的已知原版敌人；enemyType、amount |
| undo_clear_charge | 抵消本次清房观察到的普通主动充能增量；仅清房事件有效 |

itemId=0 表示随机；指定 ID 时不检查品质和道具池。随机抽取不减少池中权重，使用模组私有随机状态；概率和抽取不会更改本局种子。抽取遵循游戏道具池及角色机制（例如混沌），品质范围反向填写时按较小值到较大值处理。64 次抽取都不匹配时跳过本次动作并写入日志，不生成不符合品质的替代品。

生成/给予数量实际限制为 1–32；生命增减限制为 -48–48。red/soul/black/max 以半颗心为单位，bone/rotten 以整颗为单位。生命字段使用原版 API，减少黑心可能同时影响魂心；角色不支持的生命类型按原版处理。

支持的道具池 ID：0 宝箱、1 商店、2 Boss、3 恶魔、4 天使、5 隐藏、6 图书馆、7 贝壳游戏、8 黄金箱、9 红箱、10 乞丐、12 诅咒、26 星象。

掉落物 pickupVariant：10 心、20 金币、30 钥匙、40 炸弹、70 药丸、90 电池、300 卡牌、350 饰品。普通金币/钥匙/炸弹/红心的 subtype=1，subtype=0 表示随机；卡牌和饰品填写对应 ID；药丸填写颜色 ID。

heartType：red、soul、black、max、bone、rotten。slot：0 主主动、1 书包、2 口袋、3 第二口袋。敌人 enemyType：10 呆头、13 苍蝇、14 吐弹苍蝇、18 攻击苍蝇、21 蛆虫、22 苍蝇巢、25 爆炸苍蝇、26 血口、27 宿主、85 蜘蛛、38 婴儿。

## 控制台

本机的 EnableDebugConsole 已为 1。进入游戏后使用调试控制台输入：

```text
ew help
ew status
ew list
ew enable 1 on
ew on
```

这会启用附带的清房底座规则及本局总开关。清房不充能预设是规则 2，可单独启用：

```text
ew enable 2 on
```

示例：普通房清理后以 25% 概率生成宝箱池底座，并给予 2 金币：

```text
ew new room_clear
ew list
ew rename 3 清房奖励
ew condition 3 roomType 1
ew condition 3 chance 25
ew action 3 1 kind spawn_collectible
ew action 3 1 itemId 0
ew action 3 1 pool 0
ew addaction 3 coins
ew action 3 2 amount 2
ew enable 3 on
ew on
```

示例假设这是首次新增，实际 ID 请以 ew list 为准。

```text
ew off
ew select 3
ew copy 3
ew delete 3
ew event 3 new_room
ew condition 3 maxRun 5
ew delaction 3 2
ew search Sad Onion
ew action 3 1 itemId 1
ew characters
ew profile list
ew profile new
ew profile copy
ew profile select 1
ew profile rename 我的方案
ew profile delete
ew preset start_coins
ew export
ew import <ew export 输出的完整 JSON>
ew selftest
```

export 同时写入游戏 log.txt，可复制保存；import 替换模组配置并关闭总开关，建议先导出当前配置。selftest 运行隔离的纯逻辑测试，不修改当前局、种子、资源或配置。也可在 MCM“运行”页面点击“运行自检”，结果显示在该页“状态”中。

## 兼容性边界

模组只追加效果，不取消原版奖励、出口、完成标记或充能流程。“清房不充能”先让原版充能执行，再扣除观察到的普通主动充能增量。满充能时不会平白扣一格，计时/特殊充能不处理；如果其他模组在同一时段增加普通充能，原版 API 无法辨别该增量的来源。规则动作自己追加的充能会保留。

原版伤害回调发生在伤害判定过程中；其他模组可能随后取消伤害，因此“玩家受伤回调”不保证一定损失生命。延迟事件执行前若已离开原房间，会丢弃该事件，避免在新房间生成旧房间的奖励。模组动作引发的同步回调不递归执行规则。

第一版不支持在线或本地合作；检测到不同控制器的玩家时停止执行。单人角色的副实体可以存在，房间类动作默认作用于玩家 0；受伤、使用主动动作作用于事件相关玩家。

## 开发与验证

```bash
python3 tools/check.py
python3 tools/deploy.py
python3 tools/deploy.py --package-only
```

check 使用已有 Lua 5.3/5.4 动态库做语法检查、运行 19 项纯逻辑自检，以及使用本机游戏枚举/JSON 的模拟集成测试。模拟测试不等同于游戏实测。其他游戏路径可通过 ISAAC_GAME_DIR 环境变量提供，安装工具使用 --game-dir 参数。

## 实机验收

1. F10 能找到事件工坊，六个页面中文正常显示；“运行”页面点击“运行自检”，或控制台输入 ew selftest，应显示 19 项通过。
2. 仅开启规则 1 而不打开总开关，清房不应额外生成底座。
3. 打开总开关后清房生成底座，原版主动充能与通关奖励照常执行。
4. 开启规则 2，普通未满主动清房后不增加充能；满主动不会被误扣。
5. 添加并启用 start_coins，在本局首次启用前配置好；第一次启用增加 5 金币，反复开关和继续游戏不再增加。
6. R 重开后总开关关闭，规则编辑保留；继续游戏恢复原局开关和次数。
7. 启用前后种子相同；测试中无需使用 seed/restart/goto 等命令。

如有问题，提供版本、触发规则以及游戏日志中 [EventWorkshop] 的相关行即可。
