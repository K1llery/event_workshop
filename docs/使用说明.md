# 事件工坊 1.1.1

适用于《以撒的结合：忏悔+》单人游戏，不依赖 REPENTOGON。MCM 和原版内置控制台均可编辑规则。当前提供 **90 种事件入口、102 类参数化动作**，完整目录与限制见 [覆盖清单](覆盖清单.md)。具体实体变体、物品、状态效果是动作参数，不另计为动作类别。

功能版本以 MCM“运行”页及加载日志为准。metadata.xml 的安装版本保持已经在本机验证的 1.0.1；它与功能版本分开管理，避免再次出现 Mods 勾选回退。

## 开始使用

1. 在游戏 Mods 列表启用 Event Workshop，进入或继续单人游戏。
2. 打开 MCM，在“规则”选择、新建或启用规则。
3. 在“条件”选择事件分类和触发事件，设置筛选。
4. 在“动作”选择动作分类和动作类型，再选择需要编辑的参数。
5. 在“运行”打开“本局运行规则”。

新局和 R 重开自动关闭总开关，保存的配置和单项规则开关保留。继续游戏恢复该局开关、次数、属性加成、定时状态、延迟动作和因果信息。旧版配置自动迁移，导入兼容版本 1、2。

首次打开总开关只补触发一次 run_start。它在当前局、当前房间执行规则，不更换种子、不重开、不重置游戏。重复开关、切换方案和导入配置不会补发第二次。只有规则明确选择“传送”“换层”“改变角色”等高级动作，才会改变对应局内状态。

编辑即时保存；运行状态最多每秒写入一次，正常退出时立即保存。意外关闭可能丢失最后一秒内的运行计数。最多 20 套方案，每套 100 条规则，每条 20 个动作、20 个扩展筛选；新建和复制的规则默认禁用。切换方案、导入、关闭总开关会取消尚未执行的延迟动作。

## MCM 页面

| 页面 | 功能 |
| --- | --- |
| 运行 | 总开关、版本、种子、方案管理、自检 |
| 规则 | 选择、启用、新建、复制、删除、摘要 |
| 条件 | 事件分类、事件、检测方式、基本条件和扩展筛选 |
| 动作 | 动作分类、类型、参数选择与参数值、顺序及删除 |
| 道具 | 道具名称或 ID 搜索，应用到动作或持有条件 |
| 目录 | 敌人、实体、拾取物、道具池、卡牌、药丸效果、饰品、特效、跟班、机器、障碍、音效、角色、标记、回调编号 |
| 记录 | 最近的执行、条件不满足、失败、循环拦截及限流原因 |
| 预设 | 11 个示例预设，导出配置 |

用左右键选择数值、分类和参数，确认键执行按钮。动作页的“选择参数”只列出当前动作需要的字段，再通过下一行修改其值。小数参数步长为 0.1；控制台可填写更精确数值。延迟、间隔和冷却以逻辑帧设置，**30 帧 = 1 秒**；持续时间 duration 直接使用秒。

数字使用自然语序及半角分隔符，例如“每 3 次符合条件时执行”“执行概率: 100%”。MCM 没有通用文本输入框，控制台支持英文或 ID 搜索、英文重命名、提示文字和 JSON 导入。

目录使用原版枚举，少量名称为英文标识符。机器变体目录补齐 18 种原版机器。敌人的具体变体和子类型须填写有效组合；部分首领、剧情实体和特殊入口依赖所在房间与游戏进度。提供 ID 不代表任意组合都能成立。隐藏道具可被变化检测观察，但随机底座和直接给予会排除隐藏项。安装 EID 时可使用其可选名称翻译。

## 条件

房间、角色、持有道具和扩展筛选，可选择“全部满足”或“任一满足”。没有设置筛选时视为满足。概率、每 N 次、冷却和次数上限始终是额外限制。

| 基本字段 | 含义 |
| --- | --- |
| chance | 0–100%，0 不执行 |
| every | 每 1–999 次满足筛选的事件执行 |
| roomType | -1 不限；其他为 RoomType |
| character | -1 不限；其他为角色 ID |
| collectible | 0 不限；其他为必须持有的道具 |
| maxRoom / maxFloor / maxRun | 0 不限；每房间／层／局最多执行 1–999 次 |
| matchMode | 0 全部满足，1 任一满足 |
| cooldownFrames | 执行后的冷却，0 无冷却 |
| intervalFrames | 定时、进房定时、持续条件的时长 |
| inputAction | 按下／松开事件监听的 ButtonAction |
| randomAction | 0 顺序执行全部动作，1 每次随机选择一个动作 |

扩展筛选支持事件物品、实体类型／变体／子类型、来源、槽位、变化前后数值、变化量、标记、障碍、玩家资源与生命、充能、属性、持有物数量、变身、楼层、房间形状、敌人数、诅咒、难度、时间、自定义计数器、原版回调编号。

比较支持 eq、ne、ge、le、gt、lt、bits，以及 cross_up / cross_down；可以对单项取反。跨越阈值应选择 `after`：cross_up 表示变化前小于阈值、变化后达到或超过阈值。argument 为指定道具、饰品、变身或计数器的 ID，其他筛选忽略。

执行上限按整条规则计算，多动作只计一次；动作失败仍占用一次。离开再进入同一房间不重置上限，开关和继续游戏也不重置。冷却和延迟只在局内逻辑帧推进时流逝。

## 防止规则循环

允许正常 A → B 联动；每次自然事件创建一条因果链。同一链中每条规则最多执行一次，因此：

- 获得道具 → 给予一个道具：额外给予一次后停止。
- A 获得道具 → 增加钥匙；B 钥匙变化 → 给予道具：A、B 各执行一次，第二次到达 A 被拦截。
- 后续玩家再次自然获得道具，创建新链，规则仍可正常执行。

同步回调先进入延迟事件队列；资源、持有物变化、生成实体及后续伤害、拾取和延迟动作携带来源链。继续游戏也保留这些信息。原版缺少完整因果接口：来源不明的持续道具效果、范围攻击和世界改动，会在**当前房间保守继承已有因果链**；这可能使相关规则在该房间少触发一次，但不会阻断全部规则或原版游戏流程。

玩家再次使用物品、按键、移动／射击输入和自然定时会创建新链；规则调用物品效果时仍传递当前链。传送效果的异步进房通知最多等待 90 帧，期间来源不明的进房也可能保守继承该链。

每链最多执行 32 条规则；每帧最多处理 128 个事件、256 个动作及 256 次受控原版操作，模组受控生成最多 64 个实体；当前房间实体达到 512 时跳过额外生成，不删除已有实体。事件和延迟动作队列各最多 2048 项。超限记录在“记录”页，防止规则扇出堆积。原版道具内部和其他模组的行为仍受其自身实现影响，模拟检查不等于所有组合都经过实机验证。

## 动作

完整动作字段见 [覆盖清单](覆盖清单.md)，或 `lua EW("fields 动作名称")`。每个动作都有 delayFrames、repeatCount、repeatFrames，分别为首次延迟、执行次数、重复间隔。延迟期间离开事件房间会取消该动作；不在新房间执行旧房间的生成、目标操作或奖励。

position：0 房间中心、1 玩家位置、2 事件位置、3 随机空地。target：0 事件对象、1 玩家、2 最近敌人、3 所有敌人、4 所有拾取物、5 所有跟班、6 碰撞对象。事件对象已不存在时记录失败，不操作无效引用；范围 radius=0 表示不限。

属性与眼泪标记 scope：0 当前房间、1 当前楼层、2 当前局、3 duration 指定秒数。属性 value 为增量；tears 使用“每秒眼泪数”增量，flight 正值开启飞行、非正值关闭。属性通过原版缓存重算应用，离开作用范围或到期后移除。

底座与直接给予：itemId=0 随机，指定 ID 时忽略池与品质。随机从全部 31 个原版道具池中选择，qualityMin / qualityMax 为 0–4。使用私有随机种子、不主动减少池权重，最多尝试 64 次；找不到匹配项时记录失败。

生成／给予 amount 以 1–32 为范围；资源增减允许负数。生命 red / soul / black / max 以半颗为单位，bone / rotten / golden / broken 以整颗或整格为单位；eternal 的 1 表示一个原版白心单位。全部受原版角色机制约束。黑心字段是原版接口，移除可能影响魂心构成。

充能 slot：0 主主动、1 书包、2 口袋、3 第二口袋。清房不充能预设先让原版执行，再扣除观察到的普通充能增量；满充能不误扣，计时及特殊充能不抵消，规则自己追加的充能保留。其他模组在同一阶段产生的增量无法精确区分。

模式 mode 的含义随动作变化，动作页有说明。例如门操作：0 打开、1 关闭、2 尝试解锁、3 上锁、4 移除；计数器：0 增减、其他设置；规则启停：0 启用、其他禁用。效果“使用”与“持有”是不同动作；临时效果不等于完整持有所有道具功能。

换层使用固定、经过范围校验的原生 `stage` 命令，主动重新生成目标层；避开原版 StartStageTransition 的已记录崩溃缺陷。stageType：0 原始、1 a、2 b、4 c、5 d；废弃的 3 被拒绝。它不会由总开关自动执行。传送只选择本层已有房间，改变角色不额外补发角色开局资源。

## 检测边界

- 伤害回调发生在结算前，可能随后被其他模组取消；生命变化是另一个事件。无伤清房按“本房间是否出现非假伤害回调”判断，不等于严格只检查红心扣除。
- 敌人死亡包括环境和跟班造成的死亡，不保证玩家归属；来源无法确定时不冒充玩家击杀。
- 碰撞尝试不等于成功拾取。拾取和购买结合碰撞、消失／拾取动画与持有物变化进行推断，可能遗漏特殊角色、延迟结算和第三方修改。箱子及机器交互也标注推断。
- 障碍状态变化可检测；石头、便便、TNT 的破坏结果使用状态／移除推断，不能总是确定是谁破坏。
- 实体初始化的部分属性尚未完整，事件延迟处理不代表所有生成属性都已经定型。实体移除不等于死亡，换房移除也可能产生移除通知。
- 高级 native_callback 接收原版通知，建议用 callbackId 筛选并设置冷却；不覆盖回调返回值。失效的 MC_LEVEL_GENERATOR 不注册。游戏结束／退出使用专用事件，卸载不执行规则；结束／退出仅支持即时提示、计数器及规则启停，不再生成局内内容。
- 药丸颜色选择请求只提供抽取种子（after），不提供最终颜色；道具池等选择通知也可能随后被其他模组改写。
- 初始新局总开关关闭，进房、进层和玩家初始化不会全部补发。继续事件只在恢复的总开关已开启时执行。
- 单人副实体可存在；检测到不同控制器的合作玩家时停止规则执行。

## 控制台

本机原版控制台使用内置 lua 入口，直接输入裸 `ew help` 不会转交模组。

控制台只输出英文和 ASCII，MCM 保留中文。中文规则／方案名在控制台用 ID 标识，原名不改。自定义非 ASCII 提示在控制台显示英文占位，完整内容写入 log.txt；导出 JSON 使用 `\uXXXX` 转义，导入后中文、补充平面字符和原有转义文本保持不变。复制到控制台的内容也应使用 ASCII；中文重命名可编辑导出 JSON 的 Unicode 转义后导入。

```text
lua EW("help")
lua EW("status")
lua EW("events")
lua EW("actions")
lua EW("fields stat")
lua EW("contents machines")
lua EW("contents callbacks")
lua EW("search Sad Onion")
lua EW("list")
lua EW("trace")
lua EW("selftest")
```

selftest 运行 **27 项隔离逻辑检查**，不修改实际局、种子、资源或配置，也不验证原版 C++ 接口的全部实机表现。MCM“运行自检”按钮显示相同结果。

示例：使用卡牌后，本房间增加 1.5 幸运，延迟 1 秒执行。示例假设下一条规则 ID 为 3，实际以 list 为准。

```text
lua EW("new use_card")
lua EW("list")
lua EW("action 3 1 kind stat")
lua EW("action 3 1 stat luck")
lua EW("action 3 1 value 1.5")
lua EW("action 3 1 scope 0")
lua EW("action 3 1 delayFrames 30")
lua EW("enable 3 on")
lua EW("on")
```

示例筛选与管理：

```text

lua EW("filter 3 add heldCollectible ge 1 1")
lua EW("filter 3 add flight eq 1 1 not")
lua EW("filter 3 list")
lua EW("filter 3 delete 1")
lua EW("condition 3 matchMode 1")
lua EW("condition 3 cooldownFrames 90")
lua EW("addaction 3 keys")
lua EW("action 3 2 amount 2")

lua EW("profile select 1")
```

预设名称：clear_pedestal、no_clear_charge、start_coins、damage_coin、no_hit_key、boss_soul、five_enemies、card_luck、timed_coin、gain_item_bonus、hit_slow。预设默认禁用；gain_item_bonus 只给额外的一份伤心洋葱，不自循环。

导出同时写入游戏 log.txt 的 `[EventWorkshop] EXPORT` 行；导入替换配置、关闭总开关、重新分配不与已有因果信息冲突的规则 ID，并保留本局开局标记。配置升级前建议保存导出或使用安装备份。

## 开发与实机验收

```bash
python3 tools/check.py
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tools/deploy.py
python3 tools/deploy.py --package-only
```

检查使用已有 Lua 5.3/5.4 动态库及本机原版枚举／JSON。游戏本身为 Lua 5.3；当前本地检查库为 Lua 5.4，保留实机验收区别，不临时安装运行时。

安装脚本在复制前备份本模组源码和 data/event_workshop 存档，路径为 dist/backups；备份失败会中止安装。已有 metadata.xml 保留，包括 Steam 工坊关联；首次安装使用发行包中的已验证安装信息。

实机先确认 MCM 显示 1.1.1、八个页面正常、控制台查询和 27 项自检通过；这些不需要启用总开关。再使用一个临时方案测试普通事件 → 动作、gain_item_bonus 自循环示例、A 道具变化 → 钥匙及 B 钥匙变化 → 道具的互循环、继续游戏、属性到期和清房充能。测试种子保持可通过 status 对照；无需重开当前局。高级传送／换层应单独在测试局验证。

新增原版接口和所有物品组合尚未全部实机测试。游戏日志中的 `[EventWorkshop]` 行和“记录”页可用于排查。
