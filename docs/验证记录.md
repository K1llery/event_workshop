## 1.0.2：数字显示、菜单布局和原生控制台入口

解析本机 MCM Chinese 的二进制 BMFont 字体，确认 teammeatfont10、fusion-pixel-font/10、songti/12 三种字体均有半角冒号和括号，但没有全角冒号 U+FF1A 及全角括号 U+FF08 / U+FF09。这解释了原先分隔符没有字形、文字数字连在一起的现象。菜单显示统一转换为半角标点并加空格，原始规则名称与存档不变；增加分组空行，执行间隔按“每 3 次符合条件时执行”显示，上限为 0 时直接显示“不限”。

“触发事件”从“规则”页移到“条件”页，“规则”页保留规则选择与管理。

控制台历史确认玩家输入过 ew help、ew rename 和 ew search。原实现只注册 MC_EXECUTE_CMD；本机另一个模组的兼容实现记录了同版原生忏悔+ 1.9.7.17 不转交未知命令的问题。结合玩家反馈，原因指向原生控制台未调用模组入口，而非 EW 大小写。增加全局 EW 函数，通过内置 lua 命令进入，例如 lua EW("status")。原回调保留供能转交命令的环境使用，两条入口共用执行与错误处理，均不返回值。命令反馈写入日志，卸载时清理本模组拥有的入口。仍不依赖 REPENTOGON。

检查通过：12 个 Lua 文件语法、metadata.xml、19 项规则逻辑自检、28 项模拟集成测试、Python 编译及 git diff --check。模拟测试现在使用 Lua 控制台入口而非直接调用回调，覆盖查询、重命名、编辑、导入错误、无 MCM、卸载清理和局内种子保持；现有 MCM 检查覆盖事件页面位置、标点与执行间隔显示。

首次部署 1.0.2 后，玩家报告 Mods 勾选回退。日志仅扫描了模组 content 路径，完全没有执行 main.lua，也没有本模组 Lua 错误。只恢复 main 分支已验证的 metadata.xml、保留全部新 Lua 代码后，玩家确认可以保持勾选；恢复的文件与首次部署相比仅 version 从 1.0.2 变回 1.0.1。日志随后确认功能代码 1.0.2 已加载、MCM 菜单注册、继续本局且 master=false。此对照确认安装版本字段变动与本机回退相关，尚不能解释游戏内部原因，不能推广为所有版本的通用限制。

最终安装信息保持与已验证 1.0.1 完全一致，功能版本统一由 catalog.lua 的 C.version 提供，菜单、加载日志与打包脚本使用该值。检查脚本约束安装版本为 1.0.1，防止今后的发行版本更新误改该字段。源码、安装目录和最终 1.0.2 ZIP 保持一致。再次检查仍为 19 项逻辑自检及 28 项模拟集成通过。
